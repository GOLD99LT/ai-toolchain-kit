# 换机：恢复配置，再做一次短演示

日期：2026-11-05。本人换机优先使用 CC Switch 官方备份/恢复、客户端重新登录，以及各工具的[使用卡](../../recipes/README.md)。不要求先学习仓库 JSON，也不要求运行自研 setup 或测试。当前实际完成范围见[配置验收记录](../validation/2026-11-05-toolbox-rollout.md)；本指南不表示另一台电脑恢复已实测。

当前恢复清单应包含：官方 deep link 已纳管到 Codex、DSH 的 Playwright/Context7，以及已通过 Skills 原生开关启用到 DSH 的 `grilling`、`grill-me`；PLC 技能保持 Codex-only。保留各项自己的目标范围，不把全部技能统一切成双端。当前服务演示成功与新机客户端短例通过分开记录，具体证明范围见[本轮确认结果](cc-switch.md)。

## 旧电脑先准备什么

1. **记一份小清单。** 记录 CC Switch 版本、使用的客户端、普通技能来源、原生插件名称及来源、已启用 MCP 和独立应用。只记选择与管理者，公开资料不记录账号、机器路径或凭据；保留每项原有 `required_targets`。
2. **使用官方备份/导出。** 在 CC Switch 的设置中查找备份、恢复或数据导入导出区域，使用当前版本界面提供的功能创建可恢复备份。对应能力见[官方 v4.0.25 中文说明](https://github.com/farion1231/cc-switch/blob/v4.0.25/README_ZH.md)与其用户手册。此次未完整核实该页的按钮文字及导出包覆盖范围；以页面实际说明为准，不用猜测的 CLI 或手工写数据库替代。应用内部的自动备份若要用于换机，也须保留可由恢复功能读取的副本，不能只留在旧机。
3. **补齐备份不保证覆盖的内容。** 普通自建技能保留完整目录和资源；保存已有全局 `AGENTS.md` 等个人规则。记录各原生插件的官方获取方式。独立应用的数据按各自官方方式备份；不能假定 CC Switch 的配置备份包含插件、技能资源、所有会话和应用数据。
4. **私下保存并转移。** 本仓库内的备份、真实配置和恢复记录放在已忽略的 `.local/`，例如 `.local/backups/`；另保留自己能访问的私有副本。备份可能含账号及密钥，不放进公开 Git、聊天记录或工单。官方云同步为可选方案，无需为首次换机另开云存储账号。

在仓库根目录可检查忽略规则；下面只检查规则，不读取备份内容：

```powershell
git check-ignore .local/backups/backup-placeholder.zip
```

能输出该路径表示忽略规则匹配，但忽略规则不能保护已经被跟踪的文件。提交前仍须检查待提交清单；本指南不要求提交或公开任何备份。

## 新电脑按这个顺序恢复

| 顺序 | 操作 | 检查结果 |
| --- | --- | --- |
| 1 | 从官方入口安装所需客户端、CC Switch；选择与备份格式兼容的版本 | 应用能打开，能确认版本。旧环境为 4.0.25，不以“版本最新”推断备份兼容 |
| 2 | 新机如已有配置，先在本机另做备份，再使用 CC Switch 官方恢复/导入功能选择旧机备份 | 核对恢复预览或提示中的范围；恢复不是保证无冲突的合并 |
| 3 | 核对供应商、模型和全局提示词 | 保留自己可用的供应商与全局规则，不用仓库示例覆盖 `AGENTS.md` |
| 4 | 在客户端或服务的官方登录入口重新登录 | 以新机实际认证结果为准，不将旧会话令牌可搬运作为前提 |
| 5 | 核对普通技能，并按[原生导入步骤](cc-switch.md)补齐未恢复的独立技能 | CC Switch 中可管理，所需客户端启用；同名项不再交给 Skills CLI 更新 |
| 6 | 在所属客户端重新安装原生插件，按卡安装需要的独立应用 | 完整插件由原生管理器维护；不复制缓存内的 `SKILL.md` 冒充安装 |
| 7 | 在 MCP 页核对服务与本机运行环境，修正旧机路径；仅对缺失服务按卡使用官方 deep link 或原生入口补齐，按需认证 | 不重复导入已恢复条目；Context7 本轮曾无 key 调用成功，新机仍以实际结果为准 |
| 8 | 每个目标客户端重新打开会话，按使用卡完成一次短演示 | 实际工具调用、输出和失败原因可核对；Codex 与 DSH 分别记录 |

不依赖 CC Switch 的独立应用从[使用卡目录](../../recipes/README.md)进入各自官方安装流程，按需恢复即可；没有选用的候选不必一起安装。公开 MCP 示例在 [configs/](../../configs/README.md) 及 [configs/mcp/](../../configs/mcp/)，只用于参考字段，不能代替个人备份。

普通技能在管理器内可见，仍需确认它引用的脚本、MCP 或运行环境存在。某个原生插件暂时无法在新机获得时，明确记为待恢复，并说明使用替代入口的范围，不声称已跨客户端复制成功。

## 恢复后怎样验收与回退

选择公开网页、几行合成表格或简单文本，完成使用卡的小演示即可；不用真实公司资料、固件工程或数据库作为装好工具箱的条件。成功标准是能找到入口、能完成演示、知道输出位置及再次调用方式；MCP 握手或命令退出 0 只证明对应的一步。

要求双端的工具若只恢复了一端，另一端继续保留“待验证”及原有要求；PLC 等原本仅用于 Codex 的项维持其范围。把脱敏后的结论写入配置验收记录，原始日志和备份留在 `.local/`。

普通配置与日常恢复不以虚拟机、独立账户或复杂隔离为前提，使用必要备份和短演示即可。只有明确要做完整账户边界的恢复演练时，才另行安排相应环境；不改 `HOME` 或 `CODEX_HOME` 冒充另一台机器。

若恢复后配置异常，先停止继续修改，在 CC Switch 官方恢复入口选择本次操作前的备份，再核对原供应商和规则；插件和独立应用的回退使用各自原生方式。页面提示备份版本不兼容时，按官方升级/兼容说明处理，不手改数据库格式或删除原备份。

他人第一次使用应从[需求访谈](../../prompts/onboarding.md)和自己的工具选择开始，不领取你的私有备份。需要查看保留脚本的用途时，再读[旧自动化参考](legacy-automation.md)。
