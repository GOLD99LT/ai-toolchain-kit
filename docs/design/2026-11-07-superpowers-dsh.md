# Superpowers 接入 DeepSeek Harness

日期：2026-11-07。用户已授权研究、方案自审、执行、真实验证及成功后推送；无需逐步再次确认。

## 目标与选择

在现有 DSH 中获得可发现、能自动启动工作流的 Superpowers，保留 Codex 原生插件的管理归属。交付可重复安装的来源记录、中文使用卡、社区经验评审和真实验收结果。

比较三个方向：

1. 把 Codex 缓存里的技能复制到公共目录：只有文本发现，丢失宿主适配与自动引导，更新归属不清，拒绝。
2. 从零实现 DSH 插件：可行，但社区已有原生适配，增加维护负担，拒绝。
3. 复用 `codeAnqiang-ma/dsh-superpowers` 的固定提交：采用。原生注册 15 个技能与 bootstrap，零运行时依赖，包含完整支持文件和两份 MIT 通知；由 DSH 原生插件管理。

采用提交 `65c8ee8a5f87b0b16b44ceeca8bc10a48cec2ec9`，包自报版本仍为 `0.1.0`，其中技能元数据为 Superpowers `7.0.2` / `df2e996a174f49f05aa5d5777ca56fbb0aa972ec`。它与 npm 同版本发布包内容不同，必须用 Git 提交锁定，不能仅写版本号。具体社区依据见 [评审](../research/2026-11-07-superpowers-dsh-community.md)。

## 接入和边界

- 完整第三方源码保存在私有下载目录，不复制进本仓库；公开保存精确来源及原生安装命令。
- 安装前备份目标 profile 的 manifest、lock 和用户 patch；只让原生管理器修改目标 profile，不改模型供应商、MCP、全局规则、Codex 插件或 CC Switch 数据库。
- 先在 `.local/` 中用官方 DSH API 创建演示 profile，复用现有模型连接做合成任务验证。再安装到实际使用的 profile，验收新会话。
- 使用原生 `skill` 工具的普通名称（例如 `brainstorming`），不沿用 Codex 的命名空间调用。
- 使用已映射的 Windows `pwsh` 与 DSH 子代理工具。固定插件含旧版“完成后不能继续、深度固定 1”的描述；本机 0.2.1-rc.2 的本地 direct continuable child 支持继续，one-shot/external child 另论，深度受配置限制。实际工具 schema 与运行时策略优先；新建独立 reviewer 仍是兼容的保守做法。
- 插件采用 `systemPrompt.section` 持续引导，与上游新移植指南偏好的 user-message 注入不同。这是社区适配的已知设计取舍，不称为上游官方支持。通过实际权限与工具调用验收降低风险。

## 验收与退回

来源锁定、安装成功、CLI/profile 解析、agent 发现和任务通过分别记录。必须看到真实 `skill` 调用；模型口头说“有技能”不足以通过。

验收包括：无插件基线；安装后首轮普通功能请求触发 brainstorming 并在写代码前停留设计；明确调试请求触发 systematic-debugging；明确 TDD 请求执行失败到通过；一次真实子代理与评审；后续轮次仍可加载技能。上下文压缩、长时多代理和桌面 UI 若未测，单独标注。

失败时保留证据，使用原生 remove 停用插件；必要时恢复本轮备份。安装或连接成功不等于工作流通过。不为验收访问私人业务工程、修改硬件或部署服务。

## 方案自审

自审结论：可执行。范围限定在成熟工具复用、必要配置与中文教学；来源精确，避免与 CC Switch 重复管理；模型请求仅使用合成输入；无新增公共第三方代码或通用安装平台。主要不确定性为当前 DSH API 和模型遵循性，须以真实测试解决后才标记成功。
