## 选型方向建议

推荐按“公共基础 + 可选工作场景”组织工具组合，让换机和他人复用时可以选择需要的部分。下列划分待确认：

### 项目管理与汇报

建议从“测试资料 → 结构化台账 → 问题与进度摘要 → 汇报 PPT”切入。

候选能力：办公文件读取、数据核对与汇总、状态和问题追踪、固定模板输出、图表、可编辑的 PPT、来源追溯。

拟议验收样例：同一批输入资料生成测试问题清单和汇报稿；关键数字可以回查原始数据；缺失信息明确保留，不自动编造；PPT 能在用户实际使用的软件中打开并继续编辑。公司格式模板已确认存在，内容结构模板尚未建立；输入文件格式、数据口径和可接受的人工整理程度仍待确认。

建议分别维护内容结构和视觉格式：报告写哪些结论、进度、问题和下一步行动，与 PPT 使用什么字体、颜色和母版，是两个不同的配置项。公开工程可提供通用样例，公司实际模板和原始项目资料作为本机输入，不作为通用示例提交。

### STM32 与硬件开发

建议分别评估代码修改、编译检查、调试/板上验证、原理图/PCB 阅读、PCB 修改、BOM 整理，避免用一个“嵌入式技能”概括全部能力。

候选能力：需求影响分析、代码差异审查、调用现有编译工具、整理编译和测试记录、读取芯片资料、BOM 比较与字段检查。

拟议验收样例：一个明确的需求变更对应可审查的代码差异和实际构建记录；BOM 变更可以列出新增、删除和字段变化；PCB 修改方案通过相应设计软件的检查。具体工具和能自动完成的范围取决于用户当前的软件环境。

编译结果与硬件测试结果应单独记录。首版是否包含烧录、在线调试和直接修改 PCB，尚未确认。

### 信息搜集与个人技术实践

用户已确认先实现按需执行的“搜集 → 核实原始来源 → 筛选 → 形成实践方案”。定期订阅、推送与自动部署留作独立的后续需求。

候选能力：网页阅读与浏览器操作、资料去重、来源和日期记录、开源项目筛选、软件库文档查询、小网站功能验证、VPS 环境与操作文档。

拟议验收样例：围绕一个主题输出有原始链接、日期、部署条件及适用理由的候选清单。需要登录的网站如何接入仍待确认；持续监控、定时摘要和实际远程部署不属于已选择的首版范围。
