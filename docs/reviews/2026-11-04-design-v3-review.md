# 第三版方案严格评审记录

日期：2026-11-04（Asia/Shanghai）。对象：[第三版方案](../design/2026-11-04-ai-toolchain-design-v3.md)。

评审范围是方案、证据和可执行的验收设计；不是安装测试或效果认证。用户要求写完后单独严格评审，本轮按“写完 → 作者逐项自查 → 独立审阅 → 处理问题 → 再提交”执行。

## 1. 第二版发现是否解决

| 第二版问题 | 第三版处理 |
| --- | --- |
| 重管理、轻任务型成熟项目发现 | 新增 Understand-Anything 专项审核与 12 个具体项目比较；主方案按代码、报告、网站、资料采集组织 |
| 仅改变目录不足以隔离全局安装 | 明确安装演练采用独立 Windows 用户/可丢弃环境，覆盖技能、锁、缓存与客户端状态；无法隔离就不宣称演练完成 |
| 访谈、源记录和恢复输入关系不清 | 定义 capability/implementation/source/verification 的关联；补充普通上游、私有技能与宿主插件三类流程及 JSON 示例 |

## 2. 写完后的作者自查

主任务完整重读第三版及候选目录，并对照用户补充要求。检查后修正：

| 编号 | 问题 | 修正 |
| --- | --- | --- |
| S1 | 目标客户端只作为普通字段，可能为迁就工具而隐性缩小用户要求 | 使用 required_targets；只支持单端的工具不能替代用户要求的双端能力 |
| S2 | “完整项目沿用官方安装器”仍可能与共享技能或服务冲突 | 接入步骤明确列出占用名称、路径、服务与更新方式，先检查归属再执行 |
| S3 | 图文件可共享容易被误解为应提交真实业务图到公共工具工程 | 规定业务图、报告和索引留在相应项目/私有位置，按实际处理阶段记录数据流 |
| S4 | 数据契约虽有字段，仍缺一个具体可阅读的选择记录 | 增加私有 grilling 示例，并明确未采集校验前不能生成安装动作 |

额外核对但未作效果承诺：C/C++ 语言配置不等于 STM32 运行关系准确；Presenton 的模板重建不等于母版无损导入；图形化产品不等于网站模板；许可证可见不等于不限用途；历史 issue 不等于所有当前版本必现。

## 3. 独立审阅

独立审阅已完成。审阅者不参与写作，先独立阅读需求、第三版方案及来源材料，未先读取作者自查结论，未修改工作区；同时复核了上游关键文件。

结论：**设计可提交**。未发现 Critical 或需要阻止提交的 Important 问题，发现 1 项 Minor，主任务已修正。

| 编号 | 发现 | 处理 |
| --- | --- | --- |
| R1 / Minor | Understand-Anything 的 Codex 安装目标是共享目录，DSH 也可能发现技能；选择 Codex 不等于只向 Codex 暴露 | 在方案和专项评估中加入可见性与兼容性区别；单宿主试点使用完整隔离边界，正式接入记录实际可见客户端，不假设存在未经验证的过滤 |

审阅确认：第三版已将成熟任务项目作为主线；正确区分源码支持、发布、使用报告与本机测试；完整项目和普通 Skills 的管理边界清楚；required_targets 不得被静默缩减；第二版的隔离与数据契约问题在设计层面得到解决。

修正后主任务重新核对了相关段落及文档链接。没有尚未处理的设计阻断项。该结论只表示方案可供用户审核，不是产品效果认证、实施完成或安装授权。

- Understand-Anything、Repomix、Serena 等对实际 STM32 工程的结果。
- Docling/Presenton 对公司资料、中文内容与模板的结果。
- 各项目在本机 Windows、Codex、DSH 中的实际安装和调用。
- CC Switch 升级和真实供应商/MCP 配置保留。
- 固定来源安装、完整隔离环境中的恢复、真实换机。
- 小网站构建与服务器部署。

不能因设计评审完成就把这些项目标为通过。
