# 个人 AI 工具箱方案复核

日期：2026-11-05。对象：[个人 AI 工具箱方案](../design/2026-11-05-personal-ai-toolbox-plan.md)。

## 作者自查

本次从用户初始需求到最后纠偏重新核对，不把前轮已发布脚本当作必须继续扩建的方向。

| 复核问题 | 处理 |
| --- | --- |
| 统一管理是否仍在自研 | 普通 Skills/MCP/提示词优先 CC Switch，原生插件和完整产品使用其支持入口 |
| 是否把“可重复部署”置于“用户会用”之前 | 使用卡、菜单/命令入口和短演示成为交付；不要求用户理解 JSON 或测试系统 |
| 是否又把工具选择扩大为业务项目分析 | 业务 ZIP 保持暂停，工具演示与完整业务执行明确区分 |
| 是否因少装而忽略成熟项目 | 保留 Understand-Anything、Presenton、Docling 等具体建议及进入条件 |
| 是否承诺 CC Switch 能包办全部软件 | 明确普通资源与原生插件/独立应用的边界，按工具记录管理者 |
| 由旧管理逻辑转到 CC Switch 会否双写 | 先备份核查归属，移交后同名项由单一管理者维护；旧脚本停止主入口角色 |
| 换机是否把凭据公开 | 私有备份与公开清单分开，官方恢复能力与必要登录分别说明 |
| 是否又提出不必要的前置条件 | 普通配置用短演示，复杂安装按实际需要处理，不把完整隔离环境一概前置 |

## 独立审阅

独立上下文审阅已完成，未参与方案写作、未修改文件、未安装或分析业务 ZIP。

结论：可提交用户审阅，无 Critical/Important 阻断。发现一项 Minor：第三步的标题和措辞可能让“补充专业项目”变成必经安装步骤，与按需选择矛盾。

处理：改成有明确缺口、返工或体验改善价值时才选择专业工具，没有明确增益可跳过；不以新增工具数量作为完成条件。主任务已复核修改。

审阅确认：现成 CC Switch 与使用教学成为主线；独立产品和原生插件没有被强行统一安装；Codex/DSH 的结果分别记录；双入口和成熟项目发现仍保留；私有备份与公开手册边界清楚；不重复访谈或扩大到业务项目接管。

评审针对需求与方案，不将其当作已完成安装或兼容验证。本次没有新装工具、迁移 Skills、修改业务源码或推送远端。
