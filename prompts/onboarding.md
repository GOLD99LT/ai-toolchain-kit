# 首次使用：从自己的工作选择工具

将下面的说明交给你正在使用的助手即可，不必先安装新 Skill。目标是生成适合你自己的选择文件，再进入与换机恢复相同的计划入口；不默认套用作者的 STM32、PPT 或 VPS 需求。

## 给助手的工作说明

默认用简体中文沟通；先读取仓库 README、catalog 两份 JSON、批准设计及相关研究。只读取本轮任务需要的内容。现有证据采样日期为 2026-11-04，候选条目不是安装成功报告。

先用用户已提供的信息建立工作画像。缺少会影响选择的信息时，每轮问一至三个具体问题，允许“不需要/尚不确定”：

- 最频繁或最耗时的三个任务分别是什么？举一个真实但可脱敏的输入和理想输出。
- 当前怎样完成，时间主要花在读取、编辑、验证、协作还是部署？
- 使用哪种系统和客户端？哪些能力必须在 Codex、DSH 或其他宿主都可用？
- 输入涉及什么格式、语言、编译器/编辑器、模板或编码？哪些内容只能在本地处理？
- 已有工具、账号、运行时和可接受费用是什么？聊天订阅与 API 额度分别确认。
- 是否愿意维护独立应用、Python/Node 环境、Docker 或服务器？没有需求就不添加这些依赖。
- 用什么小样例和明确答案判断是否比当前方法更好？

不要要求用户提交 API key、公司文件或个人绝对路径。可先用合成数据定义验收；真实私有内容和路径留在本机。

## 选择与研究

1. 将每个任务写成“输入 → 处理 → 输出 → 验收”，指出现有流程的具体瓶颈。
2. 先查 catalog；已有能力满足时直接复用。相近候选比较至少包含任务匹配、Windows/客户端边界、成本、安装负责人、许可来源与失败条件。
3. 目录外的新任务继续研究，不用已有 12 个项目勉强替代。新研究优先官方文档/发布和具体使用反馈，记录日期与来源；Stars 只作发现线索，不重复抓取已有快照，也不当作质量评分。
4. 无充分证据时保持 candidate，明确缺失项；没有找到合适工具也可以保留现有方式。不同来源不虚构锁、校验或原生插件 ID。
5. 建议先试一个能证明增益的小任务，记录与当前做法的时间、遗漏、错误、返工和模型费用；不先安装整个目录。

## 输出同一份数据契约

先交付简短的方案理由与验收，再写个人 profile 至 `.local/`。公开示例只能使用无隐私数据。格式如下；此结构示例不是安装授权：

```json
{
  "schema_version": 1,
  "profile_id": "my-work",
  "capabilities": [
    {
      "capability_id": "code-context",
      "implementation_id": "repomix",
      "source_id": "repomix-1.18.1",
      "required_targets": ["codex", "dsh"],
      "required": true,
      "verification_id": "my-code-context-v1"
    }
  ]
}
```

每个三元组必须能在 catalog 中查到。不要把 npm 包名当 implementation_id。新需求研究完成后，先补有证据的能力/来源/recipe，再引用新的 ID。保留用户真正要求的 required_targets；如果实现不支持，说明生产校验会拒绝该选择，继续寻找实现，不能为了让校验通过而删掉客户端。

`required` 区分必需与可选；`verification_id` 连接后续实际结果，不证明已经验证。宿主管理、私有来源、候选完整项目必须保留相应恢复模式和人工步骤，不能伪装成 npm 锁。

## 进入实际试点

先运行 `scripts/doctor.ps1`，再运行 `scripts/setup.ps1 -ProfilePath <个人profile路径>` 查看计划。setup 默认不安装；有明确安装授权时才加 `-Apply`，`-Only` 使用 implementation_id。计划中的 manual/blocked/conflict 需要按原因处理，不能直接当成功。

`scripts/verify.ps1 -ProfilePath <个人profile路径>` 验证整个选择；安装与 CLI 均通过但 agent 未验证时返回 partial/退出码 2。`-ToolsOnly` 只验安装和 CLI 版本，通过为退出码 0，不代表用户任务或双端能力通过。

最后交付选择文件路径、采用理由、暂缓项、每项真实验证状态和下一步；不要让用户为了安装无关工具先购买账号。权限/安装授权沿用会话中已明确的范围，不重复询问已批准的步骤。
