# Dokploy：Compose 与多服务管理候选

用部署面板管理 Compose 项目、应用和数据库，适合已有此类服务需求时比较。

**状态（2026-11-05）**：候选，未连接 VPS、未部署；2026-11-04 观察 v0.30.10，不是本机运行版本。 最终状态看 [本轮配置与验证记录](../docs/validation/2026-11-05-toolbox-rollout.md)。

## 何时用

计划长期维护多个 Compose 服务、集中看部署与日志时考虑。与 Coolify 二选一比较；只需要个人静态站时先用更简单的发布方式。

## 入口与输入

选用后按官方方式部署到受支持 Linux 服务器，并从浏览器进入面板；需 Docker/Swarm 等对应条件。Windows 是管理端，没有本卡确认的 agent 原生接入。

讨论时给出合成的服务、端口、持久化与资源需求即可；真正部署所需 SSH、域名与备份留在后续私有任务。

## 两个可复制例子

以下是使用请求，示例本身不表示已经执行。尖括号内容请换成自己的实际输入；候选工具需先完成选用与配置。

**例一：比较 Compose 需求**

```text
我有一个演示方案：网页服务加数据库，使用 Compose，尚未部署。请根据已有研究说明 Dokploy 能帮助管理哪些环节，与 Coolify 各有什么采用条件；列出需要我确认的资源与维护成本，不连接服务器。
```

**例二：理解监控视图**

```text
请根据我提供的 Dokploy 脱敏演示截图，解释部署状态、容器日志和资源统计。重点说明多容器统计是否覆盖所有服务，给一份未来对照每个容器状态的检查提示，不执行远端命令。
```

## 输出与判断

示例返回选型与界面解释；未来实际面板中的项目、服务、日志和监控数据保留在服务器及私有记录中。

示例仅是教学，不能证明已安装。以后有部署任务时，用无业务数据的 Compose 样例核对访问、服务通信和逐容器状态，再检查备份与恢复。

## 管理、更新与停用

服务器运维负责人通过官方入口更新程序/镜像与维护服务；与 Coolify 避免在同一主机盲目叠装。停用或卸载前区分面板、应用、数据库和持久卷，先保留需要的数据；不交给 CC Switch 或 Skills CLI 管。

## 费用与数据

研究快照普通部分 Apache-2.0，专有部分如有则按独立条款。VPS、备份、域名、流量和可选服务另计。面板可能保存服务器密钥、环境变量与日志，应保持私有。

## 常见问题

- **监控总数和容器实际情况不符？** 历史有统计范围问题报告，逐容器核对，不凭面板总数下结论。
- **能自动把现有服务安全迁过来吗？** 本卡没有该保证，需要以后针对实际服务确认迁移和恢复。
