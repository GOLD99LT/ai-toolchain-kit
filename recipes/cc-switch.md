# CC Switch：日常工具管理入口

集中管理 Codex、DeepSeek Harness（DSH）的普通 Skills、MCP 和全局提示词，日常先从这里查看与开关工具。

**状态（2026-11-05）**：已安装 4.0.25；Playwright、Context7 已通过官方深链登记并在 Codex/DSH 启用，grilling / grill-me 已通过原生入口开启 DSH。具体 agent 对话调用仍待确认。 最终状态看 [本轮配置与验证记录](../docs/validation/2026-11-05-toolbox-rollout.md)。

## 何时用

添加普通技能、查看某个客户端启用了哪些 MCP、调整自己常用的提示词时使用。Superpowers、办公原生插件交给客户端原生管理器；独立应用在各自软件中管理。

## 入口与输入

打开 CC Switch 应用，选择要管理的客户端，再进入 Skills、MCP 或提示词页面。以 4.0.25 实际界面为准；本卡不假定它有通用外部 CLI。

准备工具名称、可信来源、需要启用的客户端和原安装负责人。接管现有条目前先核对来源与备份；账号、密钥仅在私有设置中填写。

## 两个可复制例子

以下是使用请求，示例本身不表示已经执行。尖括号内容请换成自己的实际输入；候选工具需先完成选用与配置。

**例一：找到自己的工具**

```text
请指导我在 CC Switch 4.0.25 中查看 Codex 和 DSH 的 Skills、MCP、提示词。根据我提供的脱敏条目名称，整理“工具—管理入口—在哪个客户端启用—还需验证什么”，先只查看。
```

**例二：停用一个不用的 MCP**

```text
我想在 CC Switch 中停用 <MCP名称>，目标客户端是 <Codex或DSH>。请指导我先备份该条目的配置，再通过原生界面停用；重开客户端后检查它是否仍被加载，并告诉我怎样重新启用。
```

## 输出与判断

结果是管理器内可见的条目及其启用范围；若要求助手整理清单，清单留在对话或指定的私有笔记中。

PLC 保持 Codex-only，不随普通技能纳管扩大范围。选一个普通工具，在目标客户端新对话里发起短任务，确认实际调用及输出。管理器显示启用只证明配置状态，不证明两个客户端都能完成任务。

## 管理、更新与停用

CC Switch 自身由官方应用/安装器更新。普通 Skills、MCP 和提示词优先通过原生页面管理；同名技能由一个管理器更新。原生插件内部技能不重复导入。更新前保留私有备份，更新后重试同一小任务；停用或删除条目先在对应页面操作，卸载应用通过系统原生入口，不直接改数据库。

## 费用与数据

管理器不提供模型或第三方服务额度；模型、MCP 服务及可选同步存储的费用分别核对。备份可能含凭据，保存在私有位置，不提交 Git。

## 常见问题

- **界面启用了，客户端仍看不到？** 核对所选客户端、配置是否生效以及是否需要重开会话，再查脱敏连接错误。
- **同名技能出现两份？** 先查是否来自原生插件、项目目录或 Skills CLI；确认归属后保留一个更新入口，不盲目覆盖。
