# Docling：读取扫描件与复杂表格

把难以直接阅读的 PDF、扫描页和结构化版面转换为可供后续整理的内容。

**状态（2026-11-05）**：候选，尚未安装；2026-11-04 观察 v2.147.0，不是本机验证版本。 最终状态看 [本轮配置与验证记录](../docs/validation/2026-11-05-toolbox-rollout.md)。

## 何时用

现有办公能力对扫描页、阅读顺序或复杂表格读不准时考虑。普通文本已经能读取时继续用现有工具；Docling 主要解决输入读取，不负责最终汇报排版。

## 入口与输入

选用后使用官方 Python 工具/示例，在独立环境处理文件，再把输出交给 Codex 或 DSH。当前没有已验证的两端原生集成。

准备一两页允许处理的 PDF/扫描图、希望保留的字段及输出目录。需要选定版本的 Python、解析/OCR 组件和模型资源；模型下载与许可需单独确认。

## 两个可复制例子

以下是使用请求，示例本身不表示已经执行。尖括号内容请换成自己的实际输入；候选工具需先完成选用与配置。

**例一：扫描页转阅读稿**

```text
在 Docling 已配置后，将 <我提供的一页演示扫描 PDF> 转为 Markdown，保留阅读顺序和页码对应。读不清的文字标记待确认，不自动补全。把结果保存到我指定的私有输出目录，并说明实际文件位置。
```

**例二：抽取测试表格**

```text
用 Docling 读取 <演示测试表 PDF>，整理参数名、数值、单位和来源页。逐项核对合并单元格、单元格换行和小数点，给出原值与疑点清单；只处理这几页，不读取其他文件。
```

## 输出与判断

根据实际转换方式得到 Markdown、JSON 或表格中间结果，以及页码/来源对应。输出保存在任务指定的私有目录，再用办公能力制作报告。

把一个数字、一处单位、一个多行单元格与原页并排核对。转换完成但数字或结构错误不能标为可直接使用；无法识别处应可见。

## 管理、更新与停用

由独立 Python 环境负责人按固定来源维护，模型版本和缓存另记。更新后重读同一页；停用即不调用，卸载环境前确认不被其他任务共用，模型缓存按实际位置处理。CC Switch 不接管这套 Python 环境。

## 费用与数据

代码研究快照为 MIT；模型许可另看，运行占用内存/磁盘与时间。可本地解析，不强制 LLM API；若启用远端服务或将结果交给助手，相应数据与费用需另计。

## 常见问题

- **单元格文字被粘成一行？** 历史有换行丢失报告，应回原页核查，保留原值后再整理。
- **首次运行很慢？** 检查是否正在下载模型及资源占用，先用一页短样本，不盲目扩大批量。
