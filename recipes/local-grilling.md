# 本地 grilling：把模糊想法问清楚

通过有针对性的追问，把想法收敛成目标、约束、取舍和可判断的完成条件。

**状态（2026-11-05）**：本地 grilling / grill-me 已由 CC Switch 原生入口纳管并开启 DSH，文件与管理器源 hash 一致；Codex 已有入口。实际 agent 对话使用结果仍待确认，文件一致不等于两端任务通过。 最终状态看 [本轮配置与验证记录](../docs/validation/2026-11-05-toolbox-rollout.md)。

## 何时用

不知道自己究竟要什么、几个方案难取舍、担心遗漏关键约束时用。明确的小修改可直接交给助手，不必每次完整访谈。

## 入口与输入

在能发现该技能的客户端对话中明确说“使用 grilling”。本机也已登记 grill-me 包装入口；客户端是否实际加载要在新对话中确认，不把上游同名技能当成本地修改版。

给出一个想法、希望解决的问题、已知条件和不想做的事情。已有答案不用重问；无需提交私人账号或真实公司文件。

## 两个可复制例子

以下是使用请求，示例本身不表示已经执行。尖括号内容请换成自己的实际输入；候选工具需先完成选用与配置。

**例一：厘清个人主页**

```text
使用本地 grilling 帮我检查这个想法：我想做一个个人主页，只展示简介和文章，每月维护一次，不需要登录或交易。每次只问一个最影响选择的问题，最后整理目标、取舍和完成条件。
```

**例二：找出汇报瓶颈**

```text
使用 grilling 帮我弄清周报为什么耗时。现状是把几段笔记手工搬到 PPT，听众只有5分钟。我想先选合适工具。沿用我已有信息，最后给一个能用合成资料尝试的小任务。
```

## 输出与判断

主要输出在对话中：问题与回答、明确的需求、仍有分歧的点、完成条件。需要存档时指定私有 Markdown 文件。

用上面的主页想法试一次：问题应围绕已知约束推进，最终能说清交付什么。不断重复已答问题或直接给大而全方案，说明需要收紧请求。

## 管理、更新与停用

现由 CC Switch 负责这两项的启用、同步、更新与停用；Skills CLI 不同时写同名项。更新前保留用户修改过的私有原件和管理器备份，核对实际来源与依赖，更新后重试短访谈。停用时在对应客户端关闭入口并保留原件，不拿上游版本覆盖本地修改。

## 费用与数据

技能本身是提示与工作方法，主要成本是对话模型用量；回答和输入按当前模型设置处理。私有技能全文与访谈中的工作资料不进入公开仓库。

## 常见问题

- **找不到 grilling？** 查看当前客户端的技能列表、是否启用、是否有同名覆盖，不能只根据磁盘存在判断。
- **提示缺少其他技能或工具？** 按本地 SKILL.md 的实际依赖处理，不仅复制入口文件。普通访谈可用小样例，不要求先做完整账户恢复演练。
