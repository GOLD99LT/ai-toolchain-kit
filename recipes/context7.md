# Context7 MCP：按软件库版本查用法

让智能体检索软件库文档和代码示例，减少套用错误版本 API 的情况。

**状态（2026-11-05）**：已采用 remote 无密钥路线，通过 CC Switch 官方深链登记；Codex/DSH 均 enabled，客户端配置实际存在；正常用户环境的 Codex 已识别这两个 enabled 服务。direct server 初始化发现 2 个工具，Express 检索成功；agent 对话内调用仍待确认。npm 4.5.0 仅为已核查的包版本，不表示本次采用本地包运行。 最终状态看 [本轮配置与验证记录](../docs/validation/2026-11-05-toolbox-rollout.md)。

## 何时用

开发小网站、使用框架或接入软件库，需要查指定版本用法时使用。芯片手册、Keil、CubeMX、STM32 HAL 和 EDA 的覆盖未核实，仍需厂商资料。

## 入口与输入

在已启用的目标客户端新对话中要求“使用 Context7 查询”。MCP 配置由 CC Switch 管理；不需要新人编写 JSON 或猜测 API 方法名。

给出库名、项目实际版本、具体问题与相关少量代码。需要联网；本次 remote 无密钥检索成功，但不代表无限额度或所有库都可查。以后若服务要求账号或 key，按实际条件处理。

## 两个可复制例子

以下是使用请求，示例本身不表示已经执行。尖括号内容请换成自己的实际输入；候选工具需先完成选用与配置。

**例一：查 Astro 内容用法**

```text
使用 Context7 查询我项目所用 Astro <实际版本> 的内容集合用法。先确认查到的库和版本，给一个最小示例及文档依据；如果只有其他版本，明确差异，不把它说成当前项目已兼容。
```

**例二：核对现有 API**

```text
使用 Context7 核对 <软件库名> <实际版本> 中 <函数或配置项> 的参数和返回值。比较我随后贴出的短代码，列出需要修改的地方及来源；只解释，不安装依赖、不改项目。检索不到就说未找到。
```

## 输出与判断

对话中的文档摘述、来源、适用版本及代码建议；只有另行要求时才保存到自己的项目笔记。

直接服务的 Express 检索已成功，仍需分别检查 Codex/DSH 对话内实际调用。使用时核对库和文档版本，至少复核一个 API；检索成功不等于建议代码已在项目中跑通。

## 管理、更新与停用

通过 CC Switch 的 MCP 页面管理 remote 条目；远端服务由服务方维护，本次无需本地 npm 包更新。将来若另选本地包路线，才按精确版本与 integrity 维护；服务账号和额度在服务方原生入口管理。更新后重查同一库；停用 MCP 不代表取消服务订阅，订阅需单独处理。

## 费用与数据

客户端包与远端服务分别看待，不能因为本地安装就认定免费无限使用或可完全离线。服务额度/价格以实际账号为准，助手还消耗模型额度；查询词和提交的内容会发往外部服务，避免带密钥或私有源码。

## 常见问题

- **受限沙箱查不到，是否需要重装？** 正常用户环境已识别服务，沙箱查询可能假阴性；先在现有客户端重开或新会话使用。DSH headless 初始化受阻不表示 web/desktop 配置失效，无需另建 headless profile。
- **提示认证或额度不足？** 检查当前服务配置及账号额度，保留准确错误，不自动升级付费。
- **库或版本搜不到？** 回到该版本官方文档，标明来源和覆盖缺口，不换成别的版本后宣称匹配。
