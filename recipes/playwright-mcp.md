# Playwright MCP：在对话里查看与操作网页

让智能体打开网页、点击页面元素并检查显示效果，适合动态页面和自己的小网站。

**状态（2026-11-05）**：项目内已安装 0.0.84；已通过 CC Switch 官方深链登记，Codex/DSH 均 enabled，客户端配置实际存在；正常用户环境的 Codex 已识别这两个 enabled 服务。direct server 已通过 MCP SDK 初始化（25 个工具）、读取 example.com 标题 Example Domain 和截图；agent 对话内调用仍待确认。 最终状态看 [本轮配置与验证记录](../docs/validation/2026-11-05-toolbox-rollout.md)。

## 何时用

页面需要交互、动态内容无法直接读取，或要检查网站导航和窄屏显示时使用。搜索资料可先用现有搜索入口；安装浏览器工具不等于获得定时监控。

## 入口与输入

在已启用的目标客户端新对话中要求“使用已配置的 Playwright MCP”。配置入口是 CC Switch 的 MCP 页面，实际启动参数以主任务核查的配置为准。

准备公开网页 URL 或已启动的本地网页地址、需要检查的内容。运行依赖包括匹配的 MCP 进程和浏览器；本地网页要先能在浏览器打开，登录状态不能假定已共享。

## 两个可复制例子

以下是使用请求，示例本身不表示已经执行。尖括号内容请换成自己的实际输入；候选工具需先完成选用与配置。

**例一：读取公开示例页**

```text
使用已配置的 Playwright MCP 打开 https://example.com，读出页面标题、主标题及一个可见链接的文字。请说明是否实际调用了浏览器工具；打不开就报告错误，不凭已有知识补出页面内容。
```

**例二：检查自己的页面**

```text
使用 Playwright MCP 打开 <我的本地网页地址>，检查导航链接是否可点击，并比较桌面宽度和手机宽度下是否有横向溢出。先报告发现和复现步骤；如果能保存截图，请给实际位置。不要提交表单或发布网站。
```

## 输出与判断

对话中的页面事实、来源地址与问题列表；需要截图时另指定私有目录，是否生成及文件位置由实际工具结果说明。

主任务已完成直接服务的浏览器短演示。接下来仍需分别在 Codex、DSH 对话中看到真实工具调用与可核对结果；MCP SDK 直接调用成功不等于 agent 对话任务通过。

## 管理、更新与停用

配置通过 CC Switch 的 MCP 原生入口启用、更新和停用；本地包按已记录精确版本与 integrity 维护。更新后重试 example.com；停用后重开目标客户端确认不再加载，清理包前确认没有其他客户端共用。不要同时叠装同用途 CLI。

换机安装按 [配置指南](../configs/README.md) 使用 Node.js >=22.20.0 和 `npm ci --prefix runtime/playwright-mcp --ignore-scripts --no-audit --no-fund`，再把本机 node/cli.js 路径填入 CC Switch。公开 JSON 的路径占位符不可原样导入；本机现有配置已填写真实路径。不要以 npx 临时解析替代仓库锁文件的完整性安装。

## 费用与数据

浏览器工具本身不提供模型额度；助手操作消耗当前模型用量，目标网站可能有自己的访问条件。页面内容及工具结果可能发给当前模型；示例不需要复用日常登录浏览器。

## 常见问题

- **受限沙箱查不到，是否需要重装？** 正常用户环境已识别服务，沙箱查询可能假阴性；先在现有客户端重开或新会话使用。DSH headless 初始化受阻不表示 web/desktop 配置失效，无需另建 headless profile。
- **连上 MCP 却打不开页面？** 检查浏览器是否可启动、目标地址是否可访问，本地服务是否运行。
- **X 或登录页无法读取？** 记录登录/访问限制；不能据此猜内容，也不能保证所有站点都可自动操作。
