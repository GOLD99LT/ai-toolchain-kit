# Firecrawl：服务方式获取网页资料

通过服务获取网页正文、抓取结果或结构化字段，减少自己维护采集流程。

**状态（2026-11-05）**：候选，尚未接入；现有研究没有选定可锁定的发布版本，不补猜版本号。 最终状态看 [本轮配置与验证记录](../docs/validation/2026-11-05-toolbox-rollout.md)。

## 何时用

重复采集且愿意使用托管服务/额度时比较；愿意维护服务环境时才考虑自托管。偶发查资料优先用已有浏览与搜索入口。

## 入口与输入

托管路线从服务方控制台与官方 API 使用；自托管按所选发布的官方部署说明使用。请求格式以真实服务版本为准，本卡不虚构接口或客户端插件。

准备少量公开 URL、输出字段和预算。托管通常需要账号、API key 与额度；自托管需要匹配的多服务环境，功能不能假定等于云端。

## 两个可复制例子

以下是使用请求，示例本身不表示已经执行。尖括号内容请换成自己的实际输入；候选工具需先完成选用与配置。

**例一：单页转阅读稿**

```text
在已接入的 Firecrawl 服务中读取 <公开网页URL>，输出正文、来源 URL 和采集时间。请使用当前官方支持的方式，说明实际读取范围；若失败或额度不足就报告原因，不开通新付费方案。
```

**例二：核对结构化字段**

```text
使用已配置的 Firecrawl 从我提供的3个公开页面提取标题、发布日期和最后一段中的关键字段，保留原值与来源。重点核对长文尾部是否截断；没读到的字段写未知，生成可供人工复核的表格。
```

## 输出与判断

服务返回的正文/结构化结果及助手整理的来源表；保存到指定私有目录，保留失败响应的脱敏摘要。

打开原页面核对首段和末段、一个字段和来源。HTTP 成功不代表正文完整；托管与自托管结果分别记录。

## 管理、更新与停用

托管账号、密钥和套餐在服务原生入口管理；自托管程序由服务负责人按固定来源更新。若以后接入 MCP，配置优先 CC Switch，但不因此承诺兼容。停用调用与取消套餐是两件事；自托管卸载前备份自有配置和结果。

## 费用与数据

托管按实际账号额度/套餐计费，本卡未核查现价；自托管也有服务器和维护成本。研究快照主体 AGPL-3.0、部分组件 MIT。URL、网页内容及结构化请求会发往所选服务；模型抽取还有相应数据处理范围。

## 常见问题

- **本地部署为什么没有云端功能？** 两条路线能力不同，应对照实际服务说明。
- **长文有内容却字段缺失？** 检查是否截断，缩小样本并回原文核对，不能靠模型补齐。
